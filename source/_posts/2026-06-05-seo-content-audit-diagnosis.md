内容流量下降时，最危险的动作不是“什么都不做”，而是还没确定原因就批量改标题、删文章或合并 URL。**内容审计的第一步应该是建立互相竞争的解释，再用最小证据排除错误解释。**

我的诊断顺序是：

1. 先判断是站点级、目录级还是少数页面的问题；
2. 再判断需求变了、排名变了，还是点击分配变了；
3. 最后才区分内容过时、意图错位与真正的关键词内耗。

这比先给每篇文章打一个“内容分”更慢一点，但能避免把技术问题当内容问题，也避免把正常的多页面覆盖误判为内耗。

## 四种现象看起来相似，处理却不同

### 流量下滑

这是结果，不是原因。Google 列出的可能性包括算法变化、排名变化、技术问题、安全或垃圾内容问题、季节性与需求变化。页面内容只是其中一个方向。

### 查询迁移

页面总点击下降，但原来的查询也许被新的表达方式、品牌需求或 SERP 功能替代。此时单纯提高旧关键词密度没有意义。

### 关键词内耗

多个 URL 在相同任务上竞争，搜索引擎持续切换主页面，且读者路径和内部链接也无法表达主次。关键是“相同任务”和“产生损失”，不是“两个 URL 都有展示”。

### 意图错位

页面回答了相关主题，却没有完成当前搜索者的任务。例如查询明显需要产品比较，页面却只有行业科普；或者查询需要故障排查，页面一打开就要求询盘。

四种情况可以同时存在，但必须分别收集证据。

## 第一层：先确定下滑范围

我会固定日期、Search type 和主要过滤条件，再依次比较：

- 整个站点；
- 目录或页面类型；
- 单个 URL；
- 查询簇；
- 国家与设备。

Google 建议在分析下降时扩大日期范围、与相似周期比较，并分别查看不同搜索类型。对于有季节性的 B2B 行业，只做“过去 28 天 vs 前 28 天”很容易把正常需求周期当成异常。

一个实用的范围判断：

| 现象 | 优先假设 | 先查什么 |
| --- | --- | --- |
| 多个目录同一天陡降 | 技术、手动措施、算法或数据异常 | 状态码、索引、站点变更、GSC 消息 |
| 单一目录缓慢下降 | 模板、内容老化、竞争与需求变化 | 查询簇、页面类型、模板更新 |
| 少数 URL 下降 | 页面级意图、标题、内容或内链 | URL 与 query 交叉对比 |
| 展示稳定、点击下降 | CTR、SERP 形态或品牌偏好变化 | 排名、标题、设备与查询 |
| 展示和点击一起下降 | 需求或可见性下降 | Trends、排名、索引与竞品 |

表格只是排查起点，不是因果结论。

## 第二层：建立“查询—页面”迁移视图

只看页面总量，会错过点击在页面之间重新分配。我会对重点查询簇建立一个小矩阵：

| 查询簇 | 原主页面 | 当前主页面 | 展示趋势 | 点击趋势 | 页面任务是否一致 |
| --- | --- | --- | --- | --- | --- |
| 产品类别词 | 分类页 A | 博客 B | 稳定 | 下降 | 否 |
| 选型问题 | 博客 C | 博客 D | 上升 | 稳定 | 部分重叠 |
| 型号词 | 产品页 E | 产品页 E | 下降 | 下降 | 是 |

这时才有资格谈“内耗”。如果分类页 A 与博客 B 服务不同任务，问题可能是搜索意图变化或分类页证据不足；如果 C 与 D 的标题、内容和 CTA 几乎相同，才更接近重复竞争。

GSC 的 Performance report 可以按查询、页面、国家和设备等维度观察点击、展示、CTR 与平均排名。平均排名适合发现方向，不适合单独决定删改，因为它会被查询组合和展示位置聚合。

## 诊断树：从现象到动作

```text
流量是否在多个目录同一时间下降？
├─ 是：先查技术、索引、站点变更、算法/安全与数据异常
└─ 否：是否集中在少数查询簇？
   ├─ 否：查需求、季节性、品牌与市场变化
   └─ 是：展示是否稳定？
      ├─ 是，点击下降：查 CTR、SERP 形态、标题与设备差异
      └─ 否：同一查询的主 URL 是否持续切换？
         ├─ 否：查页面意图、内容完整性和竞争变化
         └─ 是：两页是否完成同一任务？
            ├─ 否：强化分工和内部链接
            └─ 是：评估合并、重定向或重新定位
```

这个树的重点是延后不可逆动作。删除和重定向应该发生在证据之后。

## 一个假设审计示例

假设一篇“设备选型指南”三个月内点击下降 35%。进一步发现：

- 展示只下降 5%；
- 平均排名变化很小；
- 移动端 CTR 下降明显；
- 同期 SERP 出现更多产品列表；
- 网站分类页开始获得同一批商业查询，但参数和比较信息不完整。

这不支持“指南内容失效”这一单一结论。更合理的动作可能是：

1. 保留指南的选型任务，更新摘要和对比表；
2. 补足分类页的产品比较证据；
3. 从指南用清晰锚文本链接到分类页；
4. 分开观察信息型和商业型查询；
5. 一次只改一组主要变量，并记录日期。

示例数字完全是假设，不对应任何真实站点。

## 动作矩阵：更新、分拆、合并还是保留

| 证据 | 首选动作 | 不应立即做 |
| --- | --- | --- |
| 内容过时，但任务仍匹配 | 更新事实、示例、结构与摘要 | 换 URL |
| 一个页面混合两个明确任务 | 分拆，并设计双向内链 | 复制原文生成两页 |
| 两页任务、证据和 CTA 高度重复 | 选择主页面，合并有效内容并重定向 | 只加 canonical 后不改内链 |
| 两页任务互补 | 强化标题、首屏、锚文本和路径 | 为“消除内耗”强行合并 |
| 需求整体下降 | 调整投入与预期，寻找相邻需求 | 通过堆词追回旧量 |
| 技术或索引异常 | 先修复技术根因 | 大规模改写正文 |

我的优先级通常是“影响范围 × 业务价值 × 证据强度 ÷ 修改与回滚成本”。它是工作方法，不是 Google 官方指标。

## 边界与失败模式

GSC 数据会聚合，部分低量查询不会完整显示；平均排名也不是固定的逐词排名。对小站或低流量页面，短周期波动不足以支持强结论。

内容审计还常因这些做法失败：

- 混用不同日期、国家、设备或 Search type；
- 只导出当前排名词，看不到已经丢失的查询；
- 发现两个 URL 就贴上“cannibalization”标签；
- 同一次修改 title、正文、模板、内链和 CTA；
- 只关注点击恢复，不检查页面任务和线索质量；
- 删除旧页后没有迁移内部链接和有价值内容。

审计的产物不应只是一张红黄绿表，而应是一组“证据—假设—动作—复查日期”记录。

## 执行清单

- [ ] 固定比较日期、Search type、国家和设备口径
- [ ] 判断问题发生在站点、目录、页面还是查询簇
- [ ] 分开观察展示、点击、CTR 与平均排名
- [ ] 建立重点查询的主 URL 迁移视图
- [ ] 区分任务互补、任务模糊和任务重复
- [ ] 在改内容前排除技术、索引与需求变化
- [ ] 为每个动作记录假设、修改项和复查日期
- [ ] 优先做可回滚、能验证单一假设的修改
